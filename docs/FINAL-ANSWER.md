# Final architectural answer

I would combine predictive utilization with progressive safety by separating the system into a pacing engine and a non-bypassable Safety Controller. The pacing engine estimates the number of calls that may be useful based on available agent capacity, answer-rate estimates, outstanding/ringing calls and provider health. The controller independently clamps or rejects every request using current authoritative state. Agent and borrower reservations are made transactionally before any provider initiation. Calls and provider events are persisted, event IDs are idempotent, and invalid/out-of-order transitions cannot reopen terminal calls. Provider degradation reduces pacing or stops new calls, while recovery reconciles uncertain outcomes rather than blindly retrying. This keeps prediction advisory while safety remains deterministic.
